# Unreal Gold VR — approved design (2026-08-21)

> **Revision (2026-08-21, review outcome):** the original draft proposed
> forking the MIT-licensed ICBINDx11Drv. On review, the project's standing
> "study, don't copy" policy won: the render device is **written from scratch**
> against the official OldUnreal 227k SDK, with existing renderers used
> strictly as study material and credited as prior art. This makes the road
> harder on purpose — the playable mod is almost the by-product; the knowledge
> gained and shared along the way is the real goal. The text below is the
> approved, corrected design.

## Goal

Unreal Gold (OldUnreal 227k) playable in VR with true stereo rendering, 6DOF
head tracking, and **decoupled motion-controller weapon aim** (head looks
freely; the controller aims and fires; stick moves; snap/smooth turn).

Target order: **SteamVR (OpenVR) first**, OpenXR second. Headset is a Quest
connected through **Virtual Desktop** to the home test rig — the same setup as
our other projects. The dev PC (i7-3770S + GTX 1660 SUPER) builds and
smoke-tests everything; its framerates are non-diagnostic by standing rule.

## Chosen approach (A): a native VR render device — no injection

Unreal Engine 1 loads its renderer as a plugin DLL selected in
`[Engine.Engine] GameRenderDevice=`. We write our own VR render device from
scratch against the official 227k SDK, plus a small UnrealScript companion
package for gameplay-side VR behaviour. Existing renderers — including
[ICBINDx11Drv](https://github.com/metallicafan212/ICBINDx11Drv) (MIT, D3D11 —
the renderer this install already runs) — are studied and credited as prior
art; no code from them is reused. D3D11 is the friendliest texture-submission
path for both OpenVR and OpenXR.

Rejected alternatives:
- **B. External injection / present-hook (UEVR-style):** the tool of last
  resort for closed engines; strictly worse here where a documented plugin
  interface plus licensed source exists.
- **C. Generic 3D wrapper (VorpX-style):** not a mod, no motion controls;
  comparison baseline only.

## Components

1. **`VRGoldDrv` (C++, written from scratch against the 227k SDK)** — the VR render device.
   - Per frame: poll HMD pose, render the scene twice with per-eye camera
     offsets (UE1 has no view matrix — per-eye origin/basis substitution in
     the `FSceneNode`), build per-eye asymmetric projection from runtime eye
     tangents, submit both eyes to the VR compositor, keep a flat mirror
     window.
   - VR backend behind an internal interface: OpenVR implementation first,
     OpenXR implementation later — the renderer core must not care which.
   - HUD/menus (`DrawTile` output) redirected onto an in-world plane.
2. **`VRGold` (UnrealScript package + native bridge)** — gameplay layer.
   - Head tracking into view/aim plumbing (`PlayerCalcView`-side), decoupled
     weapon aim from the controller pose (laser-pointer style), controller
     button/stick bindings, snap/smooth turn, seated/standing calibration.
   - Talks to the render device DLL for poses/input via 227's native binding.
3. **Config** — INI section for IPD scale, world scale, turn mode, gun hand,
   HUD distance; sensible defaults; everything user-tunable.

## Milestones

- **M1 — Flat parity:** our from-scratch render device builds (64-bit host)
  and runs the game flat, visually comparable to the stock renderers.
- **M2 — Stereo proof:** side-by-side stereo on the flat monitor with per-eye
  camera offsets.
- **M3 — North Star:** SteamVR compositor submission + live head tracking in
  the headset.
- **M4 — Motion controls:** controller poses in, decoupled weapon aim with a
  laser sight, core bindings.
- **M5 — Comfort & playability:** snap turn, HUD-in-world polish, world-scale
  and gun-hand options, full campaign playability pass.
- **M6 — OpenXR backend:** swap-in backend; Virtual Desktop VDXR verified.

## Testing strategy

- Dev PC: build + flat-mode parity tests; SteamVR **null driver** for
  headset-free compositor testing; automated launches must delete stale
  `Running.ini` (recovery-mode trap).
- Home rig: real-headset verification per milestone (the only perf verdicts
  that count).
- Unit-testable maths (eye offsets, FRotator↔quaternion conversions,
  projection-from-tangents) gets doctest coverage in the renderer, as in
  previous projects.

## Legal / distribution

Non-commercial fan mod; requires an owned copy of Unreal Gold plus the free
OldUnreal 227k patch; redistributes **no** original assets — we ship only our
renderer DLL, script package, and INI. No third-party code is included; the
renderers studied as prior art (ICBINDx11Drv and the SDK's reference
renderers) and everyone else who helped are credited in `CREDITS.md`.

## Open questions (tracked in the dossier)

- Exact 227k-compatible SDK header set for render devices (ICBINDx11Drv
  targets UT469/HP2; confirm or port for 227k).
- Best injection point for head orientation into gameplay (render-side only
  vs. script-side `ViewRotation` — likely both, as in XIII).
- Two-pass stereo cost on the home rig (measure at M3, optimize only then).
